# Project summary

Educational Dehradun emergency-routing simulator. Flask + OSMnx/NetworkX; vanilla JavaScript + Leaflet, no build step. Simulated traffic/safety/vehicle behavior, no live emergency navigation. Read only the files relevant to each change and keep this compact map current.

## Source map
- app.py: Flask APIs, real road graph/cache/snapping/geometry, incident registry, shared world lock/revision, build_route/route_result reused by HTTP and fleet, lazy Simulation construction. Legacy optional Gemini endpoint remains unused by UI; never read/expose credentials.
- algorithms.py: BFS, DFS, Dijkstra, A*, costs, path metrics and per-expansion search_progress. Dijkstra/A* optimize weighted objectives; BFS fewest hops, DFS first path. Minimum distance is physical length only (incident multipliers excluded), but closures are always impassable. Traffic/safety use road-class proxies plus manual/automatic incidents.
- vehicle_profiles.py: per-request graph copies; ambulance 1.0 speed factor/50 km/h cap, fire .78/40 with larger local/service delays, police 1.08/55. Assumptions only; no physical clearance checks. ETA/search/compare agree; A* time heuristic uses profile speed cap. Never mutate base graph.
- simulation.py: authoritative shared fleet state, priority/FIFO/compatible-minimum-ETA dispatcher, independent movement/pause/cancel, shared-hazard replanning, seeded automatic traffic clock. Injected planner/conditions/generator/clock make tests deterministic. Request-driven advance caps unobserved gaps at 2 real seconds; no background worker.
- static/app.js: map, empty waypoint selection, route requests/stale-response ids, discovery animation, incidents/shortcuts, settings/tabs, integration with journey/graph/fleet modules and environment revision synchronization.
- static/journey.js: existing single-vehicle manual dispatch workflow; own animation clock/marker/route/stats/pause/cancel/retry. Independent of fleet resources but sees the same road conditions.
- static/fleet.js: shared-world polling every 750 ms, request queue/agent cards/events, fleet routes/markers and traffic controls. Instance ids reset sequencing after a server restart and reject retired-instance replies; snapshot sequence numbers reject old responses; unsubmitted traffic seed/interval edits survive polling; incident revision updates trigger single-journey/preview replanning once. Duplicate/late mutation replies cannot overwrite newer world state; obsolete route snapshots are retried. No automatic discovery before Calculate, and completed journey statistics survive later traffic changes.
- static/graph-view.js: separate black graph playback renderer plus createWorkingNodesOverlay (blue actual in-sector nodes in either view). Lazy cached core/context data, zoom-zero coordinates, culled/batched Path2D strokes, padded cached canvases and CSS zoom transforms. Rebuild once on moveend/zoomend/resize, not each animation frame.
- templates/index.html: dashboard markup and most styling inline. static/style.css: supplementary route effects/older styling; inspect inline CSS first.
- graph_context.py: independent display-only surrounding-road downloader/cache. Never enters routing/snapping/BOUNDS.
- README.md: setup, feature usage, states/actions/PEAS/environment classification. PROGRESS.md is historical and can describe obsolete behavior.

## Dispatch and traffic
- static/vehicle-icons.js and static/vehicles/*.svg provide basic flat top-down ambulance, fire engine and police silhouettes for fleet/manual markers and Units cards. Map artwork is 24×36 px at rest and 18×28 px while travelling (manual running phase; fleet enroute plus shared running flag), with original drag hit areas retained. Units thumbnails are 24×38 px. Inner images rotate with actual displayed movement while Leaflet owns outer positioning; transparent artwork preserves paused/waiting outlines in both map modes. No emoji vehicle markers remain.
- Fleet drag/drop (static/fleet.js): available markers draggable in real/graph views; dragend PATCH uses existing position validation/snapping and updates reset depot. Assigned/saving markers locked. Per-marker dragging/saving guards prevent polling/RAF from undoing drag/drop; final latest state snaps back on rejected drop. Release clicks consumed before waypoint/hazard handlers. Existing click-to-move retained. test_fleet_drag.cjs (5016) covers both views, poll during drag, snapped position, rejected-drop rollback, assigned lock and waypoint isolation.
- Single journey: route discovery completes → Dispatch vehicle → running/paused → completed, with remaining distance/ETA/travelled/simulated elapsed/progress. Own 10×/30×/60× speed. Clear/config/waypoint changes cancel mission and pending replies. Active/completed journey survives view switches; replay disabled during mission.
- Vehicle audio: ambulance uses rounded two-tone, fire a lower slow wail, police a quicker yelp (synthetic demo patterns, not official regional recordings). Manual journey phase and accepted authoritative fleet snapshots control independent sirens. Pause/wait/replan/cancel/reset/arrival and fleet connection failures silence affected voices. Natural siren cadence stays independent of 10×/30×/60× travel acceleration; hidden tabs/pagehide silence all voices without changing simulation state. Available/queued units are silent.
- Fleet: two ambulances, one fire brigade, one police unit at simulated snapped depots. Queue the selected destination with selected vehicle/priority/algorithm/objective, then Start dispatcher. Each agent has its own position, mission/route, clock progress, pause/resume/cancel and status. RAF replays authoritative motion_trace road samples between 750 ms polls; it never predicts travel through closures. History is bounded to 180 simulated seconds / 1,024 samples per unit and retains crossed road corners, including arrival. Pause/reset/cancel stop the renderer immediately after the authoritative reply. Show-fleet checkbox defaults off; starting shows them, focuses active journeys and scrolls the map into view. Starting an empty queue gives an explicit queue-first message. Idle units are dimmed and paused/waiting units have distinct borders; only assigned units move. Global Pause/Reset and 10×/30×/60× speed are separate from single journey.
- Priority: Critical > High > Medium > Low, FIFO for ties; pick lowest ETA among available compatible agents. Existing missions are non-preemptive. Unreachable queued jobs retry after road changes/start, not on every poll. Freed units take the next suitable request; cancelled units preserve unfinished road when subsequently assigned.
- Shared replanning preserves occupied directed-road remainder, current position/distance and pause; API plans from the next junction. started_mid_edge survives repeated replans. Occupied-road closure waits; failed plan never drives through a closure. Resume revalidates road conditions. No route waits for road changes/retry. Single-journey auto-replan-off stops until Retry route.
- Automatic traffic controls in existing Traffic drawer: Start/Pause/Reset, 5/10/20 s interval, seed. Three generated congestion incidents with 1.5–3× penalties per tick; source=automatic. Seed reproduces same events after reset for same graph. Reset deletes generated incidents only, preserving manual incidents. Pause retains current congestion. Initial state is stopped; dashboard polling advances world. All viewers share road changes.
- Formal model/UI: fully observable simulated state, sequential/dynamic, deterministic planning snapshots with seeded stochastic traffic, cooperative multi-agent fleet, discrete graph plus continuous travel interpolation. States/actions/goals/costs/PEAS explained in collapsible fleet panel and README.

## APIs
- Fleet resource editing: POST /api/fleet/units {unit_type,position:[lat,lon]} adds; PATCH /api/fleet/units/<id> {position} moves; DELETE removes. Real in-sector road-node snapping; assigned units reject edits until finish/cancel. Simulation.edit_unit maintains depots as editable reset configuration, never reuses retired ids, retries queued jobs on resource changes and allows zero vehicles. Server restart restores defaults. Fleet Add on map / per-card move/remove work in both views; placement consumes map clicks without changing waypoints, cancels via button/Escape or hazard mode; removed cards/routes/markers are cleaned up.
- GET /, /api/graph, /api/nodes, /api/graph-context: config/dashboard, core GeoJSON, all actual in-sector nodes (including isolated), backdrop. Geometry is oriented along directed roads.
- POST /api/route: start/destination, unit_type, priority, algorithm, objective. Returns profile, priority, full traces/search_progress, metrics and journey_segments (edge id, geometry, exact distance/duration, incident_multiplier). Same-node route has one coordinate/no legs. POST /api/compare uses same selected profile.
- GET/POST /api/incidents, DELETE /api/incidents/<id>, POST /api/incidents/clear. Finite in-sector coordinates, nearest real road, all parallel/reverse keys blocked for roadblock, JSON penalty=null (never Infinity), UUID ids. Cost/blocked sets rebuilt on change and revision incremented. Clear all removes all current incidents; running traffic may generate new ones later.
- GET /api/simulation: authoritative fleet/traffic/queue/events plus incidents/revision, per-unit motion_trace and instance_id. Simulation/fleet/traffic/incident responses and polling bypass caches (no-store). POST /api/fleet/requests queues; POST /api/fleet/control start/pause/reset/speed; POST /api/fleet/units/<id> pause/resume/cancel; DELETE /api/fleet/requests/<id> cancels. POST /api/traffic/control start/pause/reset.
- Flask API requests that touch routing/world are serialized with an RLock; snapshot sequence/revision preserve consistency. In-memory shared demo state resets on process restart. Use one worker (threads allowed), otherwise workers have independent worlds. Map data persists in repo caches. /api/route retains legacy .05-degree bounds pad; map/fleet/incidents use actual working bounds.
